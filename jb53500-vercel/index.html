שמים את המפתח של Gemini ב-Vercelואז Redeploy

לשונית 1, Google AI Studio: בדף API keys מעתיקים את המפתח שהכנתם בבית.

לשונית 2, Vercel:

  1. בפרויקט של המוצר פותחים Settings, ואז Environment Variables בתפריט הצד
  2. ב-Key כותבים בדיוק GEMINI_API_KEY
  3. ב-Value מדביקים את המפתח
  4. ב-Type בוחרים Secret, ובסביבות מסמנים Production ו-Preview. שומרים
  5. ב-Deployments, ליד הפריסה העליונה, לוחצים על שלוש הנקודות ואז Redeploy

אמור להופיע: שורה בטבלה עם GEMINI_API_KEY והתווית Secret. הערך מוסתר, וגם אתם כבר לא יכולים לקרוא אותו.

Secretאחרי השמירה אי אפשר לראות אותו שוב, רק להחליף. למפתחות
Configאפשר לקרוא שוב אחרי השמירה. להגדרות שאינן סוד, כמו שם המודל
Redeployמשתנה חדש נכנס רק לפריסה חדשה. גם דחיפה חדשה עושה את זה
מריצים גם במחשב? מפתח dev נפרד בקובץ .env.local, שורה אחת בלבד: GEMINI_API_KEY= והמפתח. לפי ארבעת הכללים בדף ה-Backend. Secret לא זמין בסביבת Development, ולכן מפתח נפרד.
רוצים להחליף מודל בלי לגעת בקוד? מוסיפים גם משתנה מסוג Config בשם GEMINI_MODEL, עם שם המודל. הקוד שבשלב הבא קורא אותו, ויש בו ברירת מחדל.

מבקשים מ-Claude לכתוב את הפונקציהקודם תוכנית, אחר כך קוד

בלשונית Code, במצב Manual, שולחים:

Claude, לשונית Code
הוסף למוצר פונקציית צד שרת ב-Vercel, שקוראת למודל ה-AI.

קרא קודם, מתיקיית המוצר:
- course-stack.md: הסעיפים "חוק הברזל: מפתחות", "צד השרת" ו"שכבת ה-AI".
- ARCHITECTURE.md: הסעיף "שכבת ה-AI".
- product-10-definitions.md: הסעיף "שכבת ה-AI והפרומפט המרכזי".

איך זה בנוי:
- האתר והפונקציות מתארחים יחד ב-Vercel, מאותו ריפו. הדף פונה לפונקציה בכתובת יחסית, /api/ask. בלי CORS.
- המפתח שמור ב-Vercel כ-Environment Variable מסוג Secret, בשם GEMINI_API_KEY. אל תבקש אותו, ואל תכתוב אותו בשום קובץ.
- שם המודל נקרא מ-process.env.GEMINI_MODEL, ואם הוא חסר יש ברירת מחדל בקוד.

המשימה:
1. הצג לי תוכנית: אילו קבצים תיצור או תשנה, מה הפונקציה מקבלת ומה היא מחזירה. חכה לאישור שלי.
2. צור את הפונקציה בקובץ api/ask.js, עם export default שבתוכו fetch(request), לפי התיעוד העדכני של Vercel לפרויקט בלי framework. ב-package.json יש "type": "module".
3. לפני שאתה כותב את הקריאה למודל, קרא את התיעוד העדכני של Gemini API, ובחר ברירת מחדל מבין מודלי ה-Flash העדכניים.
4. הפונקציה מקבלת רק POST עם JSON, מגבילה את אורך הקלט, ומחזירה תמיד JSON, גם בשגיאה. היא לא מחזירה את המפתח, ולא הודעת שגיאה גולמית של הספק. הפרטים הטכניים נרשמים ב-console.error.
5. חבר את הכפתור במסך הראשי: הוא פונה ל-/api/ask, מציג מצב טעינה, ומציג את התשובה או הודעת שגיאה בעברית.
6. ודא שב-.gitignore יש .env, .env.* עם החריגה !.env.example, ו-.vercel, ושיש .claude/settings.json שחוסם לך את הקריאה של .env ושל .env.*.
7. בסוף הסבר לי איך אני בודק, ופרט מה לא יכולת לבדוק בעצמך.

אל תדחוף ל-GitHub לפני שאישרתי.
Claude מבקש את המפתח? לא נותנים. כותבים לו: "המפתח שמור ב-Vercel. קרא אותו בקוד מתוך process.env, ואל תבקש אותו ממני."

process.env.GEMINI_API_KEYכך הפונקציה קוראת את הסוד. המפתח עצמו לא מופיע בשום קובץ
fetch('/api/ask'בקוד של הדף. כתובת קצרה, בלי https ובלי שם דומיין
slice או בדיקת אורךהגבלה על אורך הטקסט שנשלח למודל. בלי זה, כל גולש יכול לשלוח ספר שלם על חשבונכם
console.errorמה שנכתב כאן מופיע ב-Logs של Vercel. הגולש מקבל רק הודעה קצרה
"type": "module"בקובץ package.json, בשורש הריפו
עוצרים ושואלים לפני שמאשרים: מפתח שכתוב בקובץ. הכתובת googleapis.com בקוד של הדף. כותרות Access-Control-Allow-Origin, שכבר לא צריך. פונקציה שמחזירה ערך מתוך process.env. ספרייה חדשה שלא ביקשתם. שינוי בקבצים שלא קשורים למשימה.

זה מה ש-Claude אמור לכתוב, בערך. שם המודל והפרומפט יהיו שלכם:

const MODEL = process.env.GEMINI_MODEL || 'gemini-3.8-flash';
const ROLE = 'הפרומפט המרכזי של המוצר';

function reply(body, status = 200) {
  return Response.json(body, { status });
}

export default {
  async fetch(request) {
    if (request.method !== 'POST') {
      return reply({ error: 'POST only' }, 405);
    }

    let question = '';
    try {
      const body = await request.json();
      question = String(body.question || '').trim().slice(0, 500);
    } catch (e) {
      return reply({ error: 'bad request' }, 400);
    }
    if (!question) {
      return reply({ error: 'missing question' }, 400);
    }

    const key = process.env.GEMINI_API_KEY;
    if (!key) {
      console.error('GEMINI_API_KEY is missing');
      return reply({ error: 'server is not configured' }, 500);
    }

    const url = 'https://generativelanguage.googleapis.com/v1beta/models/'
      + MODEL + ':generateContent';
    let res;
    try {
      res = await fetch(url, {
        method: 'POST',
        headers: { 'x-goog-api-key': key, 'Content-Type': 'application/json' },
        body: JSON.stringify({
          system_instruction: { parts: [{ text: ROLE }] },
          contents: [{ parts: [{ text: question }] }],
        }),
      });
    } catch (e) {
      console.error('network error', e);
      return reply({ error: 'model did not answer' }, 502);
    }

    if (!res.ok) {
      console.error('model error', res.status, await res.text());
      return reply({ error: 'model did not answer' }, 502);
    }

    const data = await res.json();
    const parts = data.candidates?.[0]?.content?.parts || [];
    const answer = parts.map((p) => p.text || '').join('').trim();
    return reply({ answer });
  },
};

ובצד של הדף, הכפתור פונה לפונקציה כך:

async function ask(question) {
  const res = await fetch('/api/ask', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ question }),
  });
  const data = await res.json();
  return data.answer || data.error;
}
הקוד של הפונקציה גלוי בריפו, וזה בסדר. כל אחד יכול לקרוא איך היא עובדת. את המפתח אף אחד לא רואה, כי הוא לא בקוד.

  2. ברשת: פותחים את כלי המפתחים (F12, וב-Mac ‏Cmd+Option+I), עוברים ל-Network, ומפעילים שוב. מופיעה בקשה בשם ask, באותה כתובת של האתר. אין בקשה אל googleapis.com
  3. בקוד: בכלי המפתחים מחפשים בכל קובצי הדף (Ctrl+Shift+F, וב-Mac ‏Cmd+Option+F) את GEMINI_API_KEY. הוא לא מופיע. השם קיים רק בפונקציה שבשרת
  4. בלוגים: ב-Vercel, תחת Logs, מופיעה שורה לכל לחיצה שלכם

אמור להופיע: תשובה באתר, בקשה אחת ל-/api/ask, אפס מפתחות בדפדפן.
