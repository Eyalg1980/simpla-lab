מעודכן ל-5.10.2026, לפי התיעוד הרשמי של Supabase. הדשבורד משתנה מדי פעם, אז שם של כפתור יכול לזוז. העיקרון נשאר.

חלק א

ביד, בדשבורד

פעם אחת. עושים כל צעד בעצמכם, כדי לדעת מה אתם מאשרים כש-Claude יעשה אותו בשבילכם.

1

פותחים חשבון, ארגון ופרויקטפרויקט אחד למוצר שלכם

  1. נכנסים ל-supabase.com/dashboard, ונרשמים עם הג׳ימייל של הקורס
  2. יוצרים ארגון (Organization) על שם הקורס, בתוכנית Free
  3. יוצרים פרויקט חדש: שם באנגלית, סיסמה לבסיס הנתונים, ואזור באירופה
  4. את הסיסמה שומרים במקום בטוח. לא בתיקיית המוצר, ולא בצ׳אט
למה ארגון נפרד לקורס: בחלק ב Claude מקבל גישה לכל הפרויקטים שבארגון שתבחרו. ארגון שיש בו רק את פרויקט הקורס שומר על כל השאר בחוץ.

אמור להופיע: אחרי דקה או שתיים, מסך הבית של הפרויקט.

2

יוצרים טבלת תרגולטבלה אחת, שתי עמודות

  1. בתפריט הצד נכנסים ל-Table Editor, ולוחצים New table
  2. שם הטבלה: practice
  3. את העמודות id ו-created_at משאירים. Supabase מוסיף אותן לבד
  4. לוחצים Add column פעמיים: title מסוג text, ו-price מסוג int4
  5. את הסימון של Row Level Security משאירים דולק, ולוחצים Save
שמות: טבלאות ועמודות באנגלית, באותיות קטנות, עם קו תחתון במקום רווח. התוכן עצמו בעברית.
3

מכניסים חמש שורותבעברית, כמו שהמוצר ייראה

  1. פותחים את הטבלה practice ב-Table Editor
  2. מעל הטבלה לוחצים Insert, ובוחרים Insert row
  3. ממלאים title ו-price, ושומרים. חוזרים על זה חמש פעמים

אמור להופיע: חמש שורות בטבלה, כל אחת עם מספר id משלה.

4

מוצאים את הכתובת ואת המפתח הציבורישני הדברים היחידים שנכנסים לקוד של האתר

לוחצים על Connect בראש המסך, או נכנסים ל-Settings ואז API Keys.

כתובת הפרויקטhttps://xxxx.supabase.co
נכנסת לקוד של האתר
מפתח ציבוריsb_publishable_...
נכנס לקוד של האתר
מפתח סודיsb_secret_...
לא נכנס לשום מקום שאנחנו בונים
המפתח הסודי עוקף את כל המנעולים. הוא לא נכנס לקוד, לא לריפו, לא לתיקיית המוצר, ולא לצ׳אט עם Claude. הריפו שלכם ציבורי.

מפתח ארוך שמתחיל ב-eyJ שייך לשיטה הישנה: anon הוא הציבורי, ו-service_role הוא הסודי. שתי השיטות עובדות.

5

בודקים מהדפדפן, ונתקעים בכוונהככה האתר שלכם רואה את הטבלה כרגע

הטבלה מלאה, ובדשבורד רואים אותה. האתר עדיין לא. ממלאים את שלושת השדות ולוחצים על הכפתור:

בודק החיבור

הפנייה יוצאת מהדפדפן שלכם ישר לפרויקט שלכם. הדף לא שומר את מה שהקלדתם.

אמור להופיע: שגיאת permission denied, או אפס שורות. שתיהן אומרות אותו דבר: האתר עדיין לא רשאי לקרוא.

6

פותחים שלושה מנעוליםארבע שורות SQL, פעם אחת ביד

1. Grantהאם לתפקיד הזה מותר לגשת לטבלה בכלל
2. RLSמנעול על כל השורות. דולק: אף שורה לא יוצאת בלי כלל
3. Policyהכלל: אילו שורות מותר, ולמי

בתפריט הצד נכנסים ל-SQL Editor, מדביקים, ולוחצים Run:

grant select on public.practice to anon;

alter table public.practice enable row level security;

create policy "public can read practice"
on public.practice
for select to anon
using (true);

בעברית: לגולש אנונימי (anon) מותר לקרוא (select) את כל השורות (true). לא לכתוב, לא לשנות, ולא למחוק.

חוזרים לבודק שבשלב 5 ולוחצים שוב.

אמור להופיע: חמש השורות שהכנסתם.

למה מדריכים ישנים לא מזכירים את ה-grant: עד 2026 כל טבלה חדשה נחשפה לאתר אוטומטית. מ-30.5.2026 זה כבר לא כך בפרויקטים חדשים, ומ-30.10.2026 גם בפרויקטים קיימים.
