# סטאק הקורס, 53500: המסלול המשודרג

המסלול המשודרג הוא רשות. React עם TypeScript, שנבנה עם Vite ומתארח ב-Vercel.
המסמך הזה משלים את course-stack.md ולא מחליף אותו. הוא קובע רק לגבי צד הלקוח, צד השרת, הפריסה והמבנה. כל שאר הכללים שב-course-stack.md ממשיכים לחול כמו שהם: חוק המפתחות, הנתונים, הקבצים, ההרשאות, שכבת ה-AI, האוטומציות, עברית ונגישות.

עודכן: 24.10.2026

## מי עובר, ומתי

עוברים למסלול רק אחרי שהמוצר בסטאק הבסיסי באוויר ועובד: האתר ב-Vercel, לפחות פונקציה אחת, והנתונים ב-Supabase, דרך הפונקציות.
המעבר מתאים כשמתקיים לפחות אחד מאלה:

- במוצר יותר מחמישה מסכים, ויש מידע שעובר בין מסכים.
- המוצר התחיל ב-Lovable, והקוד שלו כבר כתוב ב-React.
- הסטודנט רוצה להמשיך לפיתוח, ולהכיר את הכלים שהתעשייה עובדת איתם.

לא עוברים באמצע Milestone, ולא שבוע לפני הצגה.

## למה המסלול הזה

- קומפוננטות: כל חלק במסך הוא רכיב שחוזר, כמו בפיגמה. במוצר עם הרבה מסכים זה שומר על סדר.
- TypeScript תופס טעויות לפני שהקוד רץ. Claude מריץ את הבדיקה, והסטודנט לא צריך לכתוב TypeScript בעצמו.
- כמו בסטאק הבסיסי, אתר ופונקציות בפרויקט אחד ובכתובת אחת, ולכן אין צורך בכותרות CORS.
- אלה הכלים שרוב התעשייה עובדת איתם, ו-Lovable מייצר קוד React.

המחיר: יש שלב בנייה. מה שכתוב בקובץ הוא לא בדיוק מה שרץ בדפדפן, ושגיאת בנייה עוצרת את הפריסה.

## חוק הברזל: מפתחות, ועוד כלל אחד

כל הכללים שב-course-stack.md חלים. במסלול הזה מתווסף כלל:

- כל משתנה סביבה ששמו מתחיל ב-`VITE_` נכנס לקוד שהדפדפן מקבל, וכל אחד יכול לקרוא אותו. מותר להשתמש בו רק לכתובת של Supabase ולמפתח הציבורי שלו (publishable key), ורק במוצר עם כניסת משתמשים, בשביל הכניסה. במוצר בלי כניסה אין משתני `VITE_` בכלל.
- מפתח סודי, כמו המפתח של Gemini או המפתח הסודי של Supabase, נשמר בלי הקידומת `VITE_`, ורק הפונקציה קוראת אותו, דרך `process.env`.
- הקובץ `.env.local` נשאר במחשב, ולא נכנס לריפו. ארבעת הכללים של הרצה מקומית ב-course-stack.md חלים גם כאן: `.gitignore` לפני הקומיט הראשון, חסימת הקריאה ב-`.claude/settings.json`, מפתח dev נפרד שמודבק ביד, ו-`.env.example` ריק בריפו.
- את אותם ערכים מגדירים גם בדשבורד של Vercel, ב-Environment Variables.

- הדפדפן פונה לפונקציה בכתובת יחסית, למשל `/api/ask`.

## פריסה ב-Vercel

- מחברים את הריפו לפרויקט חדש ב-Vercel. Vercel מזהה את Vite לבד: פקודת הבנייה היא `npm run build`, והתוצר בתיקייה `dist`.
- כל דחיפה ל-main בונה ומעדכנת את האתר ואת הפונקציות יחד.
- כדי שקישור ישיר למסך פנימי לא יחזיר 404, בשורש יש `vercel.json` עם הפניה לאתר, שלא נוגעת בכתובות של api:

```json
{
  "rewrites": [
    { "source": "/((?!api/).*)", "destination": "/index.html" }
  ]
}
```

- לפני כל דחיפה מריצים `npm run build` במחשב. אם הבנייה נכשלת במחשב, היא תיכשל גם ב-Vercel.
- כשהכתובת של האתר משתנה, מעדכנים אותה ב-Supabase, ברשימת ההפניות המותרות. ברמה 3 מעדכנים גם את לקוח ה-OAuth של Google.
