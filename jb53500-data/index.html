03 · מי זוכר מה

GitHub זוכר איך האפליקציה בנויה. Supabase זוכר מה קרה בה.

+

שאלה שעלתה בכיתה: אם Supabase כבר שומר, למה צריך גם GitHub? כי כל אחד מהם שומר משהו אחר.

GitHub: הקוד, עם גרסאותכל מה שכתוב בקבצים. הדף, הפונקציות בתיקייה api, וגם מבנה הטבלה, כקובץ SQL שנשמר בתיקייה. כל commit הוא גרסה, ואפשר לחזור לכל אחת.
Supabase: הנתונים, בלי גרסאותהמצב של עכשיו: הבדיחות והצחוקים שהמשתמשים יצרו. אין "גרסה קודמת" של הנתונים. בתוכנית החינמית אין גם גיבוי אוטומטי. שורה שנמחקה, נמחקה.
ההדגמה, שתי דקות
  1. מחזירים ב-GitHub את הקומיט האחרון. הקוד חוזר לגרסה הקודמת, והבדיחות בטבלה נשארות במקום
  2. מוחקים שורה אחת ב-Table Editor. שום commit לא מחזיר אותה
מי מחובר למי: GitHub מחובר ל-Vercel, וכל push הופך לפריסה. Vercel מחובר ל-Supabase דרך המפתחות. GitHub ו-Supabase לא צריכים לדבר ביניהם בקורס. GitHub הוא עמוד השדרה של הקוד, לא המרכזייה של הכול.
ומה עם "הגרסאות" ב-Supabase? רשימת ה-migrations מתעדת שינויים במבנה הטבלאות, לא בנתונים עצמם. לכן Claude שומר כל migration גם כקובץ בתיקיית הפרויקט, וככה המבנה נכנס ל-GitHub יחד עם הקוד.
04 · JSON

ככה נראית בדיחה כשהיא עוברת מהשרת לדף

+

JSON הוא הפורמט שבו השרת עונה לדף. כל לחיצה על כפתור באפליקציה מחזירה טקסט כזה.

זה מה שהדף מקבל מ-/api/random אחרי Milestone 4. בדיחה אחת, עם שלושה שדות:

/api/random
{
  "joke": "למה המחשב חולה? יש לו וירוס",
  "topic": "מחשבים",
  "source": "sheet"
}

וזו הרשימה מ-/api/top אחרי Milestone 5, בקיצור. רשימה של בדיחות, וכל אחת עם המספר שלה:

/api/top
{
  "jokes": [
    {"text": "בדיחה ראשונה", "laughs": 12},
    {"text": "בדיחה שנייה", "laughs": 7}
  ]
}

ארבעה סימנים, וזה כל הדקדוק

{ }דבר אחד, עם שדות. בדיחה אחת
[ ]רשימה של כמה דברים מאותו סוג. כל הבדיחות
"topic": "מחשבים"שדה: השם במירכאות, נקודתיים, והערך
,מפריד בין שדות ובין פריטים. אחרי האחרון לא שמים פסיק

ערך יכול להיות טקסט במירכאות, מספר בלי מירכאות כמו 12, true או false, null כשאין ערך, או עוד { } ו-[ ] בתוכו.

למה צריך את זה
  • טופס מוסכם. השרת והדף הם שתי תוכנות נפרדות. הדף יודע לחפש את הבדיחה בשדה joke, כי שניהם מסכימים על הטופס
  • כולם כבר מדברים בו. OpenAI עונה לפונקציה ב-JSON. גם Supabase מחזיר שורות כ-JSON, והפונקציה עונה לדף באותו פורמט
  • הגיליון יוצא דופן. הוא מחזיר CSV, טקסט עם פסיקים. הפונקציה של Milestone 4 הופכת אותו ל-JSON, וכך לדף לא משנה מאיפה הבדיחה הגיעה
  • קוראים, לא כותבים. את ה-JSON כותב Claude. אתם צריכים לדעת לקרוא אותו: בלוגים, בתשובות של המחברים, ובקבצים כמו package.json ו-.claude/settings.json
נסו עכשיו: פותחים בדפדפן את הכתובת של האפליקציה ב-Vercel, ומוסיפים בסופה /api/random. מה שמופיע על המסך הוא בדיוק מה שהדף מקבל.
השגיאה שתפגשו: Unexpected token '<'. הדף ציפה ל-JSON וקיבל דף שגיאה של HTML, בדרך כלל כי הכתובת של /api שגויה או שהפונקציה קרסה. בודקים ב-Logs של Vercel, ומדביקים ל-Claude את השגיאה עצמה.

מיילסטון 4, בדיחה מהמאגר:
- כפתור שני מתחת לכפתור הקיים: "בדיחה אקראית מהמאגר".
- לפני הקוד: בקש ממני את קישור העריכה של הגיליון, וקרא דרך המחבר של Google Sheets את שורה 1 ואת שלוש השורות הראשונות בלשונית jokes, כדי שהקוד יתאים לגיליון האמיתי. את הקישור אל תשמור באף קובץ.
- פונקציה api/random.js שקוראת גיליון Google שמפורסם כ-CSV, עם הכותרות topic ו-text. את הכותרות קרא בלי תלות באותיות גדולות או קטנות. הכתובת מגיעה מ-process.env.SHEET_CSV_URL, ולא כתובה בשום קובץ.
- פענוח CSV אמיתי: בדיחה יכולה להכיל פסיקים, מירכאות ושורות חדשות.
- הפונקציה שומרת את הגיליון בזיכרון לדקה. הבדיחה מוצגת עם textContent.
- הודעות קצרות בעברית כשחסרה כתובת, כשהגיליון לא מפורסם כ-CSV, וכשהוא ריק. הפרטים ב-console.error.

מיילסטון 5, האפליקציה זוכרת:
- דרך המחבר של Supabase, migration בשם create_jokes. אם יש לי יותר מפרויקט אחד, שאל באיזה.
- טבלה public.jokes: id מסוג uuid, מפתח ראשי, עם gen_random_uuid(). created_at מסוג timestamptz עם now(). topic מסוג text. text מסוג text, חובה. laughs מסוג integer, חובה, עם 0.
- RLS דולק בלי אף policy. grant select, insert, update על הטבלה ל-service_role בלבד, ו-revoke all מ-anon ומ-authenticated.
- פונקציה public.add_laugh(joke_id uuid) שמחזירה את המספר החדש: security invoker, search_path ריק ושמות מלאים. revoke execute מ-public, anon ו-authenticated, ו-grant execute ל-service_role.
- את ה-SQL שמור גם כקובץ db/create_jokes.sql. לפני ההרצה הצג לי אותו. אחרי ההרצה הרץ get_advisors והסבר בעברית מה נמצא, ועצור: אני בודק שהטבלה נעולה.
- לקוח אחד ב-lib/supabase.js עם @supabase/supabase-js, ב-dependencies. הכתובת מ-process.env.SUPABASE_URL והמפתח מ-process.env.SUPABASE_SECRET_KEY.
- api/joke.js שומר כל בדיחת AI ומחזיר גם id. אם השמירה נכשלת, הבדיחה עדיין מגיעה, והשגיאה ב-console.error.
- api/laugh.js מקבל POST עם id, בודק שזה uuid, וקורא ל-add_laugh דרך rpc. api/top.js מחזיר את חמש הבדיחות עם הכי הרבה צחוקים, רק כאלה עם צחוק אחד לפחות.
- בדף: כפתור "צחקתי" עם מונה מתחת לבדיחת AI, שננעל אחרי לחיצה, ורשימת "הכי מצחיקות" שמתעדכנת אחרי כל צחוק. בלי polling. בדיחות מהגיליון לא נשמרות.
- לפני הדחיפה עצור: אני שם את המפתח הסודי ב-Vercel. אל תבקש אותו ממני.

אמור להופיע: שני Milestones חדשים ב-MILESTONES.md, והשורה SUPABASE_SECRET_KEY= ב-.env.example. שום קוד חדש עדיין.
