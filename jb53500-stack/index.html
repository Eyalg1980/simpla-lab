חוק הברזל: מפתחות

הריפו ציבורי, וכל מה שהדפדפן מקבל גלוי לכל אדם. מפתח API של מודל הוא כסף, ומפתח סודי של בסיס נתונים הוא גישה לכל הנתונים. לכן:

מפתח סודי חי בשני מקומות בלבד

  • במשתני הסביבה של הפונקציות, ב-Vercel או ב-Netlify. הפונקציה קוראת אותו משם.
  • ב-Credentials של n8n, לאוטומציות. באוטומציה אין דפדפן, ולכן היא רשאית לפנות למודל ישירות.
  • לא בקוד, לא בקובץ הגדרות בריפו, ולא בצ׳אט. החריג היחיד: .env.local במחשב, למי שמריץ מקומית, לפי ארבעת הכללים למטה.
  • ערך שאינו סוד אבל לא שייך לקוד, כמו כתובת הפרויקט ב-Supabase או קישור לגיליון, נשמר כמשתנה סביבה מסוג Config.
  • המפתח הציבורי של Supabase נכנס לדף רק במוצר עם כניסת משתמשים, ורק בשביל הכניסה. הוא לא פותח אף טבלה.

הרצה מקומית: הקובץ .env.local

הפונקציות רצות בענן, ב-Vercel. מי שבוחר להריץ אותן גם במחשב, עם vercel dev, שם מפתח בקובץ .env.local בשורש התיקייה, ורק בארבעה תנאים:

  • .gitignore לפני הקומיט הראשון, עם .env, .env.* והחריגה !.env.example.
  • Claude לא קורא את הקובץ. בתיקייה יש .claude/settings.json שחוסם את Read(./.env) ואת Read(./.env.*). הקובץ הזה כן נכנס לריפו.
  • מפתח dev נפרד, עם שם משלו, שמודבק ביד. Claude לא כותב אותו, לא קורא אותו ולא מבקש אותו.
  • .env.example בריפו, עם שמות המפתחות הסודיים בלבד, בלי ערכים ובלי הערות. .env.local מכיל את אותן שורות ושום דבר נוסף. ערך שאינו סוד נשמר ב-Vercel כ-Config, גם בסביבת Development.

בענן אין קובץ .env: מפתח ה-production ב-Vercel, מסוג Secret, ב-Production וב-Preview.

מילון קצר: בכל המסמך, "פונקציה" היא פונקציה ב-Vercel או ב-Netlify. בוחרים אחת מהן לכל הפרויקט, לא את שתיהן.

HTML, CSS ו-JavaScript ברירת המחדל

מה הוא עושה
HTML הוא המבנה, CSS הוא העיצוב, ו-JavaScript הוא ההתנהגות: לחיצה, טעינת נתונים, פנייה לפונקציה.
למה הוא

הכללים
  • בלי React, בלי Next.js ובלי כלי בנייה.
  • הדף מימין לשמאל, עם גופן עברי אמיתי.

Vercel Functions ברירת המחדל

פונקציות שרת שיושבות באותו ריפו של האתר, ומתפרסמות בכל דחיפה.

מה הוא עושה
קובץ JavaScript אחד בתיקיית api שבשורש הריפו הוא פונקציה. הקובץ api/ask.js מקבל את הכתובת /api/ask.
למה הוא
קובץ אחד, בלי שרת לנהל ובלי כלי נוסף. הסוד נשמר כמשתנה סביבה, והמדריך והמצגת של הקורס בנויים עליו.
הכללים
  • בשורש הריפו package.json עם "type": "module". בלי framework ובלי שלב בנייה.
  • מתחילים מפונקציה אחת. עוד פונקציה רק כשדרישת Must מחייבת.
  • מחזירה תמיד JSON, גם בשגיאה. לא מחזירה את המפתח, ולא שגיאה גולמית של ספק.
  • הדף פונה אליה בכתובת יחסית, כמו /api/ask. בלי כותרות CORS ובלי OPTIONS, כי הכל באותה כתובת.
  • קוד שכמה פונקציות משתמשות בו, כמו החיבור ל-Supabase, יושב בתיקייה lib, מחוץ ל-api.
  • פונקציה שמשנה נתונים מקבלת רק POST, ובודקת כל שדה.
  • מגבילה את אורך הקלט שהיא שולחת למודל.
  • אחרי שינוי במשתנה סביבה צריך Redeploy. עד אז רץ הערך הקודם.
מגבלות
  • גוף בקשה עד 4.5MB. לכן קובץ לא נשלח לפונקציה, רק הכתובת שלו.
  • התוכנית החינמית, Hobby, לשימוש אישי ולא מסחרי. מוצר שגובה כסף או מציג פרסומות צריך תוכנית בתשלום.

Supabase ברירת המחדל

בסיס נתונים מסוג Postgres, עם התחברות משתמשים ואחסון קבצים, בדשבורד אחד.

מה הוא עושה
מחזיק את הטבלאות של המוצר. רק הפונקציות ניגשות אליו, עם המפתח הסודי. הדפדפן לא פונה אליו ישירות.
למה הוא
Postgres אמיתי, עם התחברות משתמשים וקבצים במקום אחד, ומחבר שדרכו Claude בונה את הטבלאות. המדריך בדף הדאטה.
הנעילה
בכל טבלה RLS דולק, בלי אף Policy. Grant רק ל-service_role, התפקיד של המפתח הסודי, ו-revoke מ-anon ומ-authenticated. מ-30.10.2026 Supabase לא נותנת את ה-grant הזה אוטומטית, ולכן כותבים אותו בכל migration.
הכללים
  • עד שלוש טבלאות. אם נראה שצריך ארבע, עוצרים ושואלים.
  • רשימה ששייכת לשורה אחת נשמרת בעמודת JSON באותה שורה, לא בטבלה נפרדת.
  • שמות טבלאות ושדות באנגלית, באותיות קטנות עם קו תחתון. התוכן בעברית.
  • בונים את הטבלה לפני המסך, ותמיד יש חמש שורות דוגמה לפחות.
  • פעולה ששני משתמשים יכולים לעשות באותו רגע נכתבת כפונקציה בבסיס הנתונים, עם עדכון מותנה אחד, והשרת קורא לה דרך rpc.
  • המפתח הסודי, sb_secret_, נשמר רק ב-Vercel כ-Secret, והכתובת כ-Config.
  • Supabase מציע לתת grant ל-anon? לא מקבלים. זו עצה לאתר שמדבר איתו ישירות.
מגבלות
בתוכנית החינמית שני פרויקטים פעילים, ופרויקט מושהה אחרי כשבוע בלי פעילות. יום לפני הצגה בודקים שהוא פעיל.
תעבורה
בתוכנית החינמית 5GB בחודש של תעבורה יוצאת (Egress), לכל הארגון. הפונקציה שולפת רק את העמודות והשורות שהמסך צריך, והדף לא שואל אותה שוב ושוב בטיימר. החריגה הראשונה מקבלת תקופת חסד, והשנייה מגבילה את הפרויקט מיד.

Supabase Storage לקבצים

האחסון של Supabase, לקבצים שמשתמשים מעלים: תמונה, קבלה, מסמך.

הכללים
  • בתיקייה פרטית. לא בריפו ולא בטבלה.
  • תמונה מוקטנת בדפדפן לפני ההעלאה, לרוחב של כ-1,600 פיקסל.
  • ההעלאה לא עוברת דרך הפונקציה: היא יוצרת כתובת העלאה חתומה וקצרת מועד, והדפדפן מעלה אליה.
  • הפונקציה מקבלת את נתיב הקובץ וקוראת אותו בעצמה, עם המפתח הסודי. לא את הקובץ בגוף הבקשה.
  • בקורס מעלים רק קבצי דמה. לא מסמך רפואי, לא קבלה עם פרטי אשראי, ולא מסמך של עסק אמיתי.

n8n אוטומציות

כלי ויזואלי לבניית תרחישים: נודים שמחוברים זה לזה, וכל אחד עושה פעולה אחת.

מה הוא עושה
אוטומציה מתוזמנת, אירועית או ידנית. למשל: טופס נשלח, שורה נכנסת לטבלה, ונשלח מייל המשך.
מפתחות
n8n רשאי לפנות למודל ולשירותים ישירות, עם מפתח שנשמר ב-Credentials שלו.
Google ומייל
חיבור לחשבון Google רק דרך n8n, ורק לחשבון אחד, של בעל המוצר. המייל יוצא מחשבון ה-Gmail של הסטודנט, לכתובות בדיקה בלבד, בלי שירות דיוור נוסף.
הכלל
אוטומציה רצה בתדירות הנמוכה ביותר שמספיקה להדגמה. נכנס במודול האוטומציות.
מתי n8n
כשיש תזמון, מייל, הודעה או חיבור לחשבון Google. פעולה שקורית כתגובה ישירה למשתמש, כמו קריאה למודל או שמירה ב-Supabase, נכתבת בפונקציה.
איפה רץ
  • בזמן הבנייה, במחשב: npx n8n, והעורך ב-localhost:5678. חינם ובלי הגבלת הרצות, אבל רק כשהמחשב דולק, והאתר החי לא מגיע אליו.
  • כשהמוצר באוויר, ב-Railway: מתבנית n8n שכוללת מסד נתונים, אחרת התהליכים נמחקים בכל פריסה. מ-5 דולר לחודש. מעבירים את התהליכים כקובצי JSON, ואת ה-Credentials מגדירים מחדש.
  • n8n Cloud אינו ברירת המחדל: אחרי הניסיון יש תשלום חודשי ומכסת הרצות.
  • מקור שחסום מחוץ לישראל נשאר ב-n8n שבמחשב.
מהאתר
הפונקציה פונה ל-Webhook של n8n, לא הדפדפן. ה-Webhook מוגן ב-Header Auth, והסוד נשמר כ-Secret ב-Vercel וב-Credentials של n8n.
